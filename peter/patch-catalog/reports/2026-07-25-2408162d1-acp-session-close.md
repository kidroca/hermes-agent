## Local patch summary

The adapter now advertises ACP close capability. `session/close` marks the active state closing, rejects new work, clears queued follow-ups, signals cancellation/interrupt, drains registered prompt tasks, and performs resource teardown off the asyncio event loop. It calls memory-provider shutdown and `AIAgent.close()`, removes active state and task-cwd registration, and bounds recent in-process close tombstones.

Durable history is never deleted. Existing rows are ended with `end_reason='acp_close'`; unused provisional sessions remain absent from SQLite. Repeated/concurrent close requests share one cleanup task. Explicit `session/load` or `session/resume` can reopen rows ended by ACP close, while implicit prompt lookup cannot resurrect them. Compression boundaries are deliberately preserved: rows ended for `compression` are never reopened by this patch.

## Upstream overlap

The installed ACP SDK already defines `session/close` and close capability negotiation, so this patch fills an adapter gap rather than adding a private protocol extension. Upstream issue [#29363](https://github.com/NousResearch/hermes-agent/issues/29363) (closed) documents the broader resource-leak class at session end, especially MCP subprocesses; this patch reuses Hermes' existing `AIAgent.close()` cleanup rather than duplicating process-specific teardown. No exact upstream Hermes ACP close implementation was found during the catalogue pass.

## Recommendation

Keep `2408162d1` until upstream provides equivalent ACP close semantics. Drop it independently when upstream guarantees cancellation/drain before teardown, no history deletion, bounded in-memory state, idempotent close, explicit reopen only for ACP-close boundaries, and preservation of compression lineage.
