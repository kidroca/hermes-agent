## Local patch summary

When explicit `agent.session_cwd` is present, forward it unchanged. Otherwise, only normalized `platform == "cli"` uses the canonical `agent.runtime_cwd.resolve_agent_cwd()` and forwards its string result under `suppress(Exception)`. The kwargs are generic and reach all providers, not just Hindsight. Messaging, cron and subagent platforms do not receive an ambient fallback.

This reuses the existing resolver, including fallback from invalid or inaccessible/remote `TERMINAL_CWD` to the local launch cwd; it does not introduce a new remote-workspace policy. Provider initialization remains fail-open if cwd resolution raises.

The five smoke tests exercised the real installed Hindsight settings lookup using disposable marker repositories, **not actual Git worktrees**: trusted repository and linked-marker location selected the override, an untrusted worktree-shaped location selected fallback, nested scratch inherited repository configuration, and outside scratch selected fallback. Slack received no ambient cwd. These tests do **not** establish real provider initialization, live CLI/Kanban operation, or retention delivery. Personal `.hindsight` configuration stays ignored; `trusted_project_dirs` must include the actual worktree root rather than assuming trust inheritance from another checkout.
